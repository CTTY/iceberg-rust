# iceberg-ffi

A C ABI over [apache/iceberg-rust](https://github.com/apache/iceberg-rust),
built as a static library and linked into the `iceberg_rs` DuckDB extension.
The header `iceberg_ffi.h` is generated by cbindgen in `build.rs` and written to
`target/<triple>/<profile>/ffi-headers/`, next to `libiceberg_ffi.a`.

The crate contains no engine-specific code. Everything the engine must supply
(memory for strings and errors, a logger) arrives as C function pointers.

## Conventions

**Handles.** Every object that outlives a call is passed as an opaque pointer.
`Shared<T>` is backed by an `Arc<T>`: the engine owns one strong reference per
handle it received and releases it with the matching `iceberg_*_free`
function. `Exclusive<T>` is backed by a `Box<T>`: single owner, consumed by
the function documented as consuming it or by its free function. Null is a
valid handle value and is reported as `IcebergErrorCodeInvalidHandle` rather
than dereferenced.

**Results.** Fallible functions return a struct `{ tag, ok, err }`. The header
has one such struct per payload type (`IcebergResultRuntime`,
`IcebergResultU64`, ...) so that it stays plain C. On the `Err` arm `ok` holds a
placeholder (null or zero) and `err` holds the engine error object; `err` is
null only when no error allocator was reachable, which happens when the runtime
handle itself was null.

**Errors.** Rust never allocates error memory. The engine registers an
`IcebergAllocateErrorFn` when it creates the runtime; on failure the crate
calls it with an `IcebergErrorCode` and a message and returns the pointer the
engine produced. The engine owns that object. The allocator pointer must not be
null (it is a plain function pointer, not an optional one) and must not unwind;
only the log callback is optional. Codes `0..ICEBERG_ERROR_CODE_COUNT`
are contiguous so the engine can keep a string table indexed by code, and a
unit test keeps the count in step with the enum.

**Strings.** Strings enter the crate as `IcebergStringSlice { ptr, len }`:
borrowed UTF-8, not NUL-terminated, valid only for the duration of the call.
Strings leave the crate through an `IcebergAllocateStringFn` the caller
passes, so the engine decides what owns the copy.

**Runtime.** The engine creates one tokio runtime per database with
`iceberg_runtime_new(workers, blocking, alloc_error, log_cb, log_ctx)` and
passes it to every call that needs async work. `log_ctx` is an opaque engine
pointer handed back as the first argument of every `log_cb` invocation; it must
stay valid until `iceberg_runtime_free` returns. Calls drive futures with
`block_on` on the engine's thread; calling the FFI from inside a tokio worker is
detected and reported as `IcebergErrorCodePreconditionFailed` instead of
deadlocking.
`iceberg_runtime_free` releases the engine's reference and, if it was the last
one, shuts the worker threads down with a short grace period.

**Logging.** `tracing` events emitted by iceberg-rust are forwarded to the
`log_cb` of the runtime whose work produced them (the callback is attached to
the runtime's worker threads and to the calling thread for the duration of
each `block_on`). Levels use DuckDB's numeric values.

**Panics.** Every `extern "C"` function body runs under `catch_unwind`; a panic
becomes an error result with code `IcebergErrorCodePanic`. Nothing that can
panic runs before the guard: handle resolution and the copy of the error
allocator happen inside it (the `with_runtime!` macro), so a panic in the
prologue is still reported instead of aborting. The crate also
denies `clippy::unwrap_used`, `clippy::expect_used` and `clippy::panic`.

**Enums.** All `#[repr(C)]` enums carry explicit discriminants, and cbindgen
prefixes variants with the enum name (`IcebergLogLevelDebug`), so the header
never defines a bare identifier that could collide with a host macro.

## Functions

| Function | Purpose |
|---|---|
| `iceberg_runtime_new` | create the runtime; returns `IcebergResultRuntime` |
| `iceberg_runtime_free` | release the runtime handle |
| `iceberg_runtime_smoke` | spawn a task and return 42; proves `block_on` from an engine thread |
| `iceberg_spec_smoke` | build a schema with `iceberg::spec` and return its highest field id |
| `iceberg_ffi_version` | the crate version through an `IcebergAllocateStringFn` |

## Development

```sh
cargo build --release              # also writes target/release/ffi-headers/iceberg_ffi.h
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

The regular extension build (`make release` at the repository root) runs cargo
through CMake with `--locked` and the Rust target triple derived from the
DuckDB platform. `Cargo.lock` is committed and authoritative.

To develop against a local checkout of iceberg-rust, uncomment the `[patch]`
block at the bottom of `Cargo.toml` and point it at the crate directory.

The dependency graph must not contain `opendal`, `rustls`, `aws-lc-sys` or any
`aws-sdk-*` crate (`make check-deps` at the repository root asserts this).
File IO is provided by the engine, and no TLS or cloud SDK is linked.
