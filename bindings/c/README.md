# iceberg-ffi

A C ABI over [apache/iceberg-rust](https://github.com/apache/iceberg-rust),
built as a static library and linked into the `iceberg_rs` DuckDB extension.
The header `iceberg_ffi.h` is generated by cbindgen in `build.rs` and written to
`target/<triple>/<profile>/ffi-headers/`, next to `libiceberg_ffi.a`.

The crate contains no engine-specific code. Everything the engine must supply
(memory for strings and errors, a logger) arrives as C function pointers.

## Conventions

**Handles.** Every object that outlives a call is passed as an opaque pointer.
`Shared<T>` is backed by an `Arc<T>`: the engine owns one strong reference per
handle it received and releases it with the matching `iceberg_*_free`
function. `Exclusive<T>` is backed by a `Box<T>`: single owner, consumed by
the function documented as consuming it or by its free function. Null is a
valid handle value and is reported as `IcebergErrorCodeInvalidHandle` rather
than dereferenced.

**Results.** Fallible functions return a struct `{ tag, ok, err }`. The header
has one such struct per payload type (`IcebergResultRuntime`,
`IcebergResultU64`, ...) so that it stays plain C. On the `Err` arm `ok` holds a
placeholder (null or zero) and `err` holds the engine error object; `err` is
null only when no error allocator was reachable, which happens when the runtime
handle itself was null.

**Errors.** Rust never allocates error memory. The engine registers an
`IcebergAllocateErrorFn` when it creates the runtime; on failure the crate
calls it with an `IcebergErrorCode` and a message and returns the pointer the
engine produced. The engine owns that object. The allocator pointer must not be
null (it is a plain function pointer, not an optional one) and must not unwind;
only the log callback is optional. Codes `0..ICEBERG_ERROR_CODE_COUNT`
are contiguous so the engine can keep a string table indexed by code, and a
unit test keeps the count in step with the enum.

**Strings.** Strings enter the crate as `IcebergStringSlice { ptr, len }`:
borrowed UTF-8, not NUL-terminated, valid only for the duration of the call.
Strings leave the crate through an `IcebergAllocateStringFn` the caller
passes, so the engine decides what owns the copy.

**Runtime.** The engine creates one tokio runtime per database with
`iceberg_runtime_new(workers, blocking, alloc_error, log_cb, log_ctx)` and
passes it to every call that needs async work. `log_ctx` is an opaque engine
pointer handed back as the first argument of every `log_cb` invocation; it must
stay valid until `iceberg_runtime_free` returns. Calls drive futures with
`block_on` on the engine's thread; calling the FFI from inside a tokio worker is
detected and reported as `IcebergErrorCodePreconditionFailed` instead of
deadlocking.
`iceberg_runtime_free` releases the engine's reference and, if it was the last
one, shuts the worker threads down with a short grace period.

**Logging.** `tracing` events emitted by iceberg-rust are forwarded to the
`log_cb` of the runtime whose work produced them (the callback is attached to
the runtime's worker threads and to the calling thread for the duration of
each `block_on`). Levels use DuckDB's numeric values.

**Panics.** Every `extern "C"` function body runs under `catch_unwind`; a panic
becomes an error result with code `IcebergErrorCodePanic`. Nothing that can
panic runs before the guard: handle resolution and the copy of the error
allocator happen inside it (the `with_runtime!`, `with_table!`,
`with_scan_builder!`, `with_scan!` and `with_file_task!` macros), so a panic
in the prologue is still reported instead of aborting. The crate also denies
`clippy::unwrap_used`, `clippy::expect_used` and `clippy::panic`.

**Enums.** All `#[repr(C)]` enums carry explicit discriminants, and cbindgen
prefixes variants with the enum name (`IcebergLogLevelDebug`), so the header
never defines a bare identifier that could collide with a host macro.

## File system vtable

The crate performs no IO itself. The engine fills in an
`IcebergFileSystemVTable { ctx, open, file_size, read_at, close, exists,
error_message, release }` and Rust implements iceberg-rust's `Storage`,
`StorageFactory` and `FileRead` traits on top of it (`storage.rs`:
`DuckDbStorage`, `DuckDbStorageFactory`, `DuckDbFileRead`, `file_io()`), so
metadata, manifests and data files are all read through the engine's file
system, with its path schemes, credentials and caches. The storage is
read-only: `write`, `writer`, `delete`, `delete_prefix`, `delete_stream` and
`new_output` fail with `FeatureUnsupported`.

**Contract.**

- Every entry may be called from any thread, including tokio blocking-pool
  threads the engine never created. Calls that take a file handle are never
  made concurrently for the same handle; different handles, `open`, `exists`
  and `error_message` may run concurrently.
- Each fallible entry returns an `IcebergIoStatus` (`Ok`, `NotFound`,
  `PermissionDenied`, `Other`). After any non-`Ok` status Rust calls
  `error_message(ctx, alloc)` immediately, on the same thread and before any
  other vtable call on that thread, so the engine can keep the last message
  in thread-local storage. `error_message` may return null; otherwise it
  returns the pointer produced by the allocator it was handed.
- `read_at(ctx, file, offset, buf, len, out_read)` may read fewer bytes than
  requested; Rust retries until the buffer is full and treats zero bytes as
  end of file.
- `ctx` stays valid until `release(ctx)`, which is called exactly once, after
  every file has been closed, when the last `DuckDbStorage` clone (and the
  last reader or `InputFile` derived from it) is dropped. Each file handle is
  closed exactly once.
- `close` runs inline when a reader is dropped, possibly on an async worker
  thread, so it must be cheap (release a descriptor, no network IO). All
  other entries run on tokio's blocking pool via `spawn_blocking`.
- Callbacks must not throw or unwind; report failures through the status.

**Error mapping.** `NotFound` becomes `iceberg::ErrorKind::DataInvalid` with
the message `file does not exist: <path>: <engine message>`, matching
iceberg-rust's own local file system storage. `PermissionDenied` and `Other`
become `ErrorKind::Unexpected` with the engine message appended. A short read
that hits end of file before the buffer is full is `DataInvalid` (`unexpected
end of file`).

**Relocation.** `DuckDbStorage::new(vtable, Some((from, to)))` rewrites every
path that starts with `from` (at a `/` boundary) to start with `to` before it
reaches the engine; trailing `/` on either prefix is ignored. The logical
path is kept on `InputFile::location()`.

## Table

`iceberg_table_load(runtime, fs, metadata_location, relocate_from,
relocate_to)` reads one `*.metadata.json` file through the vtable (gzip is
detected from the content, not the name) and returns an
`IcebergResultTable` whose `ok` is an `IcebergSharedTable` handle. The call
takes ownership of `fs.ctx`: `release` runs exactly once, from
`iceberg_table_free` when the last reference goes away or, if loading fails
for any reason including a null runtime, before `iceberg_table_load`
returns. `relocate_from`/`relocate_to` are both empty (no relocation) or both
set; one of each is `IcebergErrorCodeInvalidArgument`. Invalid UTF-8 in any
argument is `IcebergErrorCodeInvalidArgument` too.

The table keeps a copy of the runtime's error allocator, so the accessors
below need only the table handle and are synchronous. Accessors that return
a plain value (`format_version`, `location`, `property`,
`current_snapshot_id`) report a null handle as `0`/null/absent; the others
return a result struct. `IcebergResultUnit` has only `tag` and `err`.

Optional integers travel as `IcebergOptionalI64`/`IcebergOptionalI32`
(`{ has_value, value }`, `value` is zero when absent).

Collections are delivered through callbacks:

- `iceberg_table_visit_snapshots(table, ctx, cb)` calls `cb(ctx, snapshot_id,
  parent_id, sequence_number, timestamp_ms, manifest_list, operation,
  schema_id)` once per snapshot, sorted by `(sequence_number, timestamp_ms,
  snapshot_id)`. `operation` is `append`, `replace`, `overwrite` or `delete`.
- `iceberg_table_visit_partition_spec(table, spec_id, ctx, cb)` calls
  `cb(ctx, field_id, source_id, name, transform)` per partition field, in
  spec order; `transform` is the spec's textual form (`identity`,
  `bucket[4]`, `day`, ...).
- `iceberg_table_visit_schema` is described below.

String slices passed to callbacks are valid only during the callback, and
callbacks must not unwind. Unknown snapshot, schema and partition spec ids
are `IcebergErrorCodeInvalidArgument`.

## Schema visitor

`iceberg_table_visit_schema(table, schema_id, visitor)` delivers a schema
(`schema_id` absent selects the current one) through an
`IcebergSchemaVisitor { ctx, make_field_list, visit_struct, visit_list,
visit_map, visit_primitive }` and returns, in `IcebergResultUsize`, the id of
the root field list. The engine never sees Rust types: it builds its own tree
from these calls.

**List protocol.** Fields are delivered bottom-up into *field lists* the
engine owns and identifies with a `size_t` of its choosing:

1. For every struct (including the schema root), list or map, Rust first
   calls `make_field_list(ctx, reserve)` and remembers the returned id.
2. It then calls one `visit_*(ctx, sibling_list, name, field_id, required,
   ...)` per child, in declaration order, with that id as `sibling_list`.
   Children are always delivered before their parent, so when
   `visit_struct(..., child_list)`, `visit_list(..., element_id,
   element_required, child_list)` or `visit_map(..., key_id, value_id,
   value_required, child_list)` arrives, `child_list` is already complete.
3. The function returns the root list id; its entries are the top-level
   columns.

**Naming.** A list type is delivered as a one-entry list holding its element
field, named `element`; a map type as a two-entry list holding `key` then
`value` (keys are always required). Those are the names the Iceberg
specification uses; the ids are the field ids recorded in the schema.

**Primitives.** `visit_primitive(ctx, sibling_list, name, field_id, required,
kind, precision, scale, width)` carries an `IcebergPrimitiveKind`
(`Boolean = 0` ... `Unknown = 16`, `Variant = 17`); `precision`/`scale` are set
for `Decimal`, `width` for `Fixed`, and all three are zero otherwise.
Variant is reported as a primitive because it has no child fields. Geometry
and geography columns are `IcebergErrorCodeFeatureUnsupported`. Callbacks
made before an error are not undone; the engine should discard its lists.

## Literals

Primitive values cross the boundary as `IcebergLiteral { kind, is_null, i,
u_hi, u_lo, f, bytes, precision, scale }`, tagged by an `IcebergLiteralKind`
whose discriminants equal the matching `IcebergPrimitiveKind` values
(`Boolean = 0` ... `Binary = 15`). Only the fields the kind documents are
meaningful; the rest are zero or empty:

| kind | payload |
|---|---|
| `Boolean`, `Int`, `Long` | `i` (0/1 for booleans) |
| `Date` | `i`, days since the Unix epoch |
| `Time` | `i`, microseconds since midnight |
| `Timestamp`, `Timestamptz` | `i`, microseconds since the epoch |
| `TimestampNs`, `TimestamptzNs` | `i`, nanoseconds since the epoch |
| `Float`, `Double` | `f` (floats widened to 64 bits) |
| `Decimal` | `u_hi`/`u_lo`: the two's-complement 128-bit unscaled mantissa split into high and low halves; `precision`, `scale` |
| `String` | `bytes`, UTF-8 |
| `Uuid` | `bytes`, exactly 16 raw bytes, big-endian |
| `Fixed`, `Binary` | `bytes`, raw |

`bytes` reuses `IcebergStringSlice` and need not be UTF-8 for the last three
kinds. A literal with `is_null` set carries no value: the predicate builder
rejects it, and partition constants never deliver one (null constants are
skipped).

## Predicate builder

`iceberg_scan_builder_set_predicate(builder, ctx, visitor)` calls
`visitor(ctx, state)` immediately, on the calling thread. `state` is an
opaque `IcebergPredicateState`, an arena of column, literal and predicate
nodes that the visitor fills through the `iceberg_pred_*` constructors; each
returns the `size_t` id of the node it created and the visitor returns the id
of the root predicate.

- `iceberg_pred_column(state, path_parts, n)` adds a column named by `n`
  path parts joined with `.` (`n >= 1`).
- `iceberg_pred_literal(state, literal)` adds an `IcebergLiteral`.
- `iceberg_pred_lt/le/gt/ge/eq/ne/starts_with/not_starts_with(state, column,
  literal)` and `iceberg_pred_is_null/not_null/is_nan/not_nan(state, column)`
  take node ids.
- `iceberg_pred_in/not_in(state, column, literals, n)` take an array of `n`
  literal node ids.
- `iceberg_pred_and/or(state, children, n)` fold `n` predicate node ids;
  `and` of nothing is `TRUE`, `or` of nothing is `FALSE`.
- `iceberg_pred_not(state, child)` negates with inverse operators (`NOT (a <
  5)` becomes `a >= 5`), `iceberg_pred_always_true/false(state)` are the
  constants.

**Failure semantics.** A constructor that cannot do its job (invalid or
wrong-kind node id, null pointer with `n > 0`, null or unrepresentable
literal) records the first failure and returns `ICEBERG_PRED_NONE`
(`SIZE_MAX`, defined in the header). From then on every constructor on that
state is a no-op returning the same sentinel, and `set_predicate` reports
`IcebergErrorCodeInvalidArgument` with the recorded message; the builder's
previous predicate is kept. The engine therefore need not check every return
value. On a state that has *not* failed, a visitor that returns
`ICEBERG_PRED_NONE` means "no predicate" and clears any earlier one; a root
that names a column or literal node is `InvalidArgument`.

## Scan

`iceberg_scan_builder_new(table)` returns an `IcebergExclusiveScanBuilder`:
a plain configuration record with the defaults current snapshot, every
column, case-sensitive names, no predicate. iceberg-rust's own scan builder
borrows the table, so nothing is bound until build time; the setters only
store values:

- `iceberg_scan_builder_snapshot_id(b, id)`: time travel; the snapshot's own
  schema is used for binding and projection.
- `iceberg_scan_builder_select_field_ids(b, ids, n)`: project only these
  top-level columns, in this order (`n == 0` projects nothing; replaces an
  earlier selection).
- `iceberg_scan_builder_case_sensitive(b, bool)`.
- `iceberg_scan_builder_set_predicate(b, ctx, visitor)`, see above.

`iceberg_scan_builder_build(runtime, builder)` **consumes** the builder on
every path (including a null runtime; `iceberg_scan_builder_free` is only
for builders that are never built), binds the configuration and plans
**eagerly**: the manifest list and manifests are read through the table's
file system and every file task is collected before the call returns, so
the resulting `IcebergSharedScan` is immutable and safe to read from any
thread. `runtime` must be the runtime the table was loaded with. Errors:

- a predicate that does not bind to the snapshot schema (unknown column,
  literal of the wrong type, decimal of the wrong scale) is
  `IcebergErrorCodePredicateBindFailed`: the engine should retry without a
  predicate and filter the rows itself;
- a nested field id in the selection is `IcebergErrorCodeFeatureUnsupported`,
  an unknown field id or snapshot id `IcebergErrorCodeInvalidArgument`.

The planned predicate and task count are logged at `Debug` under the target
`iceberg_ffi::scan`: `planning files snapshot=.. predicate=..` before the
manifests are read and `planned files tasks=N build_us=.. plan_files_us=..`
after, where `build_us` is the time spent binding the predicate and building
the iceberg-rust scan and `plan_files_us` the time spent in `plan_files`
(manifest list and manifest reads, pruning). `iceberg_table_load` logs
`loaded table metadata elapsed_us=.. snapshots=N` under
`iceberg_ffi::table`. Fields are rendered as `key=value` after the message,
new fields are only ever appended, and times are in microseconds.

**Scan accessors.** `iceberg_scan_file_task_count(s)`,
`iceberg_scan_snapshot_id(s)` (an `IcebergOptionalI64`: a table without a
snapshot plans to an empty scan), and `iceberg_scan_equality_field_ids(s,
out, cap)`, the sorted union of the equality field ids of every equality
delete file in the scan. Id arrays use a two-call pattern: the function
copies at most `cap` ids into `out` and returns the total count; a null
`out` is treated as `cap == 0`, so the sizing call may pass null with any
`cap`. Tasks are ordered by data file path so indexes are
stable; `iceberg_scan_file_task(s, index, ctx, cb)` delivers one as `cb(ctx,
info, task)` where `info` is an `IcebergFileTaskInfo { path, file_size,
start, length, record_count, data_sequence_number, first_row_id,
partition_spec_id, n_positional_deletes, n_equality_deletes, format }`
valid only during the callback, and `task` is an `IcebergSharedFileTask`
the engine now owns and frees with `iceberg_file_task_free`. Planned tasks
always cover a whole file (`start == 0`, `length == file_size`) and carry a
record count; a task that does not is reported as
`FeatureUnsupported`/`DataInvalid` instead of being delivered.

**Task accessors.** `iceberg_file_task_project_field_ids(t, out, cap)` (two
call pattern; every top-level column when nothing was selected);
`iceberg_file_task_visit_partition_constants(t, ctx, cb)` calls `cb(ctx,
source_field_id, literal)` for each identity-transformed partition field in
ascending source field id order, skipping NULL values and every non-identity
transform (bucket, truncate, time transforms cannot reconstruct the column);
`iceberg_file_task_visit_deletes(t, ctx, cb)` calls `cb(ctx, path, content,
format, file_size, referenced_data_file, content_offset, content_size,
equality_ids, n_equality_ids)` once per delete file in manifest order
(`content` is an `IcebergDeleteContent`, `PositionDeletes = 1` or
`EqualityDeletes = 2`; `referenced_data_file` is empty and
`content_offset`/`content_size` absent when not recorded; `equality_ids` is
null unless the file holds equality deletes).

A task handle keeps the table, and with it the engine file system, alive:
`iceberg_scan_free` and `iceberg_table_free` may run before the last
`iceberg_file_task_free`.

## Development

```sh
cargo build --release              # also writes target/release/ffi-headers/iceberg_ffi.h
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

The regular extension build (`make release` at the repository root) runs cargo
through CMake with `--locked` and the Rust target triple derived from the
DuckDB platform. `Cargo.lock` is committed and authoritative.

To develop against a local checkout of iceberg-rust, uncomment the `[patch]`
block at the bottom of `Cargo.toml` and point it at the crate directory.

`plan_bench` is an ignored test that plans one table repeatedly through the
`std::fs` test vtable and prints the microseconds and vtable calls (opens,
reads, closes) per iteration plus the median; it is the driver to attach a
profiler to when attributing planning time. The metadata file must record
absolute data paths (the benchmark tables do; the test fixtures do not):

```sh
ICEBERG_FFI_BENCH_METADATA=/abs/path/to/metadata/00007-....metadata.json \
ICEBERG_FFI_BENCH_ITERS=20 cargo test --release -- --ignored plan_bench --nocapture
```

Every iteration loads a fresh table, as the engine does for every query.
With `ICEBERG_FFI_BENCH_RELOAD=0` one table is reused: iceberg-rust caches
the manifest list and manifests per `Table` instance, so only the first
iteration reads them and the later ones measure pruning alone.

The dependency graph must not contain `opendal`, `rustls`, `aws-lc-sys` or any
`aws-sdk-*` crate (`make check-deps` at the repository root asserts this).
File IO is provided by the engine, and no TLS or cloud SDK is linked.
